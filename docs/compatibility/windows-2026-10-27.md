The report identified duplicate menu locks from different launcher environments,
missed scheduled checks, and task refusals without diagnostic codes. It also
identified Fable selection for title helpers and mixed installation components.
The supplied patches were reviewed as evidence rather than applied automatically.

Source regressions reproduce the menu lock, Router catch-up and missing task-error
details. Executable PowerShell fixtures exercise owned-instance enumeration,
completed-instance races and refusal of unknown errors. These fixtures do not
prove the original intermittent Task Scheduler failure's historical cause.

Before release acceptance, require native Windows CI and actual desktop tests
for one tray icon after updating, sign-in startup, missed-check recovery, both
switch directions, title routing, guarded attachment recovery and coherent task
runtime paths. Check that a startup warning follows the menu rather than delaying it.
Windows Server CI cannot replace Windows 11 desktop acceptance.

The audit also found test assumptions about Git, text encoding and native
resources. Regression checks keep candidate verification running without Git,
read shared documents as UTF-8, and isolate Express cadence from native-resource
maintenance. Only tests that execute Git integration skip when Git is absent.
These local boundary simulations do not establish a clean native Windows suite.

Main acceptance now also runs the complete core suite and native process,
dialog and key-permission contracts under a temporary standard Windows account.
The child must confirm its account and lack of administrator rights. Git is a
required CI prerequisite. Existing administrator Task Scheduler checks remain.
The new job must pass; adding it does not establish a successful Windows run.
Its first hosted run exposed home-folder initialization after installer imports.
The child now initializes its own loaded profile before importing test fixtures.
A fresh-process regression reproduces and checks that startup order locally.
Administrator installer CI also found a missing session stub in a warning fixture
and a real task-start failure. The fixture is corrected. The native task test now
reports numeric Task Scheduler results, instance counts and log presence on failure.
A separate closed-descriptor regression reproduced a launcher bug before the fix:
its new log could reuse stdout or stderr, then be closed before the first event.
The launcher now keeps those redirected descriptors open. The historical device
startup cause remains unverified until native results or device evidence confirms it.

The administrator task test reported state 4, an active heartbeat and one running

Owned shortcut recovery has separate binary, concurrent-edit, malformed-record

The recovery APIs alone do not establish an all-or-nothing installation.
The installer now uses them for required Windows completion. Local workflow checks
cover staging, receipt publication, failed entry-point readback, retained recovery
after scheduler failure, concurrent catalogue edits and separate attachment failure.
These tests simulate Windows service and shell boundaries. They do not prove a
complete installation on the affected PC; native and functional acceptance remain open.

Windows CI exposed a recovery-record line-ending comparison failure. CRLF completion
and rollback regressions reproduced it locally and pass with byte-exact comparisons.
Local switch checks now refuse mixed components before app access, reject a stale
serving version before forward switching, and permit coherent offline reverse recovery.
They also cover older helper dialogs, removal during an earlier update download,
and safe scheduler timeout stages. These are simulated boundaries and executable
PowerShell fixtures. Standard-user Windows CI and affected-PC acceptance remain required.
