The report identified duplicate menu locks from different launcher environments,
missed scheduled checks, and task refusals without diagnostic codes. It also
identified Fable selection for title helpers and mixed installation components.
The supplied patches were reviewed as evidence rather than applied automatically.

Source regressions reproduce the menu lock, Router catch-up and missing task-error
details. Executable PowerShell fixtures exercise owned-instance enumeration,
completed-instance races and refusal of unknown errors. These fixtures do not
prove the original intermittent Task Scheduler failure's historical cause.

Before release acceptance, require native Windows CI and actual desktop tests
for one tray icon after updating, sign-in startup, missed-check recovery, both
switch directions, title routing, guarded attachment recovery and coherent task
runtime paths. Check that a startup warning follows the menu rather than delaying it.
Windows Server CI cannot replace Windows 11 desktop acceptance.

The audit also found test assumptions about Git, text encoding and native
resources. Regression checks keep candidate verification running without Git,
read shared documents as UTF-8, and isolate Express cadence from native-resource
maintenance. Only tests that execute Git integration skip when Git is absent.
These local boundary simulations do not establish a clean native Windows suite.

Main acceptance now also runs the complete core suite and native process,
dialog and key-permission contracts under a temporary standard Windows account.
The child must confirm its account and lack of administrator rights. Git is a
required CI prerequisite. Existing administrator Task Scheduler checks remain.
The new job must pass; adding it does not establish a successful Windows run.
